# 対応範囲と検証

[English](BETA_SUPPORT.en.md)

この文書では、Mac版がWindows版とどこまで同じかを、どうやって確かめているかを説明します。

## 何と比べているか

- 比べる相手は、**元のWindows版プラグイン（`.aex`）そのもの**です。
- Windows用のプログラムはMacでは直接動かないため、エミュレーター（命令を1つずつ再現して実行する仕組み）の上で動かしています。
- 同じ入力と設定をWindows版とMac版の両方に渡し、出力をバイト単位で比べます。出力される範囲（どこからどこまで描いたか）も比べます。
- 「1ビットも違わない」ことを合格とします。誤差の許容はしていません。

## 何を試しているか

テストの条件は、乱数で自動的に作っています。

- **素材**：ふつうの画像に加え、半透明、32 bpcの明るすぎる値や特殊な値（NaNなど）を含むもの
- **設定値**：各プラグインのパラメーターを、UIで選べる範囲からランダムに選ぶ
- **色深度**：8／16／32 bpc
- **サイズ**：1×1から1920×1080まで。幅と高さはそれぞれ奇数・偶数を半々で選び、1ピクセル幅の細長い画像も含む
- **AEの描画条件**：
  - プレビュー解像度（フル、1/2、1/3、1/4、1/8、縦横で違う倍率）
  - 画像の一部だけの描画（拡大表示や、画面の一部だけが見えているとき）
  - プラグインが周りの余白を求めたときの、広げた出力
  - 行の末尾に余白があるメモリ配置

見つかった食い違いは、再現する最小の例まで自動で小さくして保存しています。保存した例は、変更のたびにすべて再生して確認しています。

## 結果

AEがふだん使う描画経路（Smart Render）での結果です。OLMSmootherだけは、もう一方の通常経路で比べています。

- 奇数・偶数のサイズを中心にした3000件のテストと、部分描画を中心にした1000件のテストで、Windows版が描画できた条件はすべて一致しました。
  - 途中で見つかった食い違いは、すべて直しました。
- Windows版自身がエラーになる、あるいはエミュレーター上で時間内に終わらない条件は、比べられないため数に入れていません。

## 実際のAfter Effectsでの確認

- macOS版After Effects 2026で、10本すべてが読み込まれ、適用・レンダーできることを確認しています。
- 1920×1080と3840×2160の実寸で、本物のプラグインを動かして調べました。描画を断るケースと処理時間を測り、見つかった問題は直しています。

## 比べていないこと

- Windows版After Effectsの上で実際に描画した出力そのものとは、比べていません。比べているのは、元のプラグインのプログラムをエミュレーターで動かした結果です。
- エミュレーターで扱えるのは1920×1080までです。それより大きいサイズは、同じ処理が大きな画像でも成り立つことを前提にしています。
- GPUレンダー、AEの色管理、素材の読み込みや書き出しの違いは、対象外です。

制限の一覧は[既知の制限](../KNOWN_LIMITATIONS.md)を見てください。
