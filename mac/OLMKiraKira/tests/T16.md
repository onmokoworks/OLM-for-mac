# T16: UI Angle materialization

The original `PARAMS_SETUP` declares Glow Rotation (slot 40, disk ID 1) as
`PF_Param_ANGLE`. Its getter `181232670` copies the signed 16.16 word without
normalizing to degrees. Caller `18114e860` obtains it through `1811542b0`.
Thus a UI value of 17 reaches the original renderer as 1114112. The former Mac
float slider delivered 17. The fix restores the Angle declaration and reads
the raw word in both Classic and Smart parameter readers. Rendering arithmetic
is unchanged. Untyped historical test inputs retain their float-field contract;
they do not prove native saved-project migration.

Run with MAIN's `tools/emulation/.venv/bin/python`, from this worktree:

```sh
S="$PWD/orchestra/state/T16-kirakira-multidirection-gain-mismatch"
mkdir -p "$S"
export TMPDIR="$S" PYTHONDONTWRITEBYTECODE=1 OLM_TEST_JOBS=1
python -B mac/OLMKiraKira/tests/t16_rotation_witness.py > "$S/rotation.json"
python -B mac/OLMKiraKira/tests/t16_matrix.py --scratch "$S/matrix" > "$S/matrix.log" 2>&1
python -B mac/OLMKiraKira/tests/t16_regression.py --scratch "$S/regression" > "$S/regression.log" 2>&1
python -B mac/OLMKiraKira/tests/replay_corpora.py --scratch "$S/replay" > "$S/replay.log" 2>&1
```

The UI corpus uses the external T18 source PNG, premultiplied explicitly after
Pillow conversion to RGBA8. Source/fixture/AEX/worker hashes are pinned in
`t16_corpus.json`; no source footage is copied into the repository. These are
comparable input worlds, not reconstructed AE color-management/opacity outputs.
The gain animation is sampled at values 18/22/26 (0/0.5/1 seconds); this does not
test AE keyframe interpolation. Each run builds parent and corrected source
hosts, calls their actual `PARAMS_SETUP`, then materializes the declared type.
This avoids the historical fuzz adapter's deliberate raw-fixed mapping, which
masked the UI mismatch. No expected image values are injected into production.

Expected: original Angle setup plus seven exact getter observations; 33 new
observations = 29 byte-exact Smart renders and four unchanged refusals for the
brief's injected Merge Mode 3. The original UI declares only Merge Modes 1–2.
Those four refusals are separately reported and never counted as exact. All
390 saved corpus records replay unchanged; before/after comparison covers 780
routes. Their inherited Classic mismatches remain visible.

The retained fixture actually uses gain 1.25, Merge Mode 2, Approximated Input,
and Vertical Length animation 12→20. It does not contain the gain animation
described in the ticket. At 1080p the corresponding emulator discrepancy falls
from 154354 pixels / maximum 57 to zero. Gain 1 still has maximum 47 before the
fix. Single directional rays also differ, while zero rays and Highlight alone
match: this is a parameter-boundary error, not combined-ray rounding.

Native AE rendering, reopening old Mac projects with the former slider type,
and support for injected out-of-UI Merge Mode 3 remain separate verification.
