# OLMKiraKira Endgame Control Coverage Audit

- Date: 2026-07-10
- Scope: Windows parameter manifests/default/range evidence, current Mac UI/source schema, and current binary-grounded IR.
- Lane rule: hotspot compose is frozen. This audit does not authorize image tuning, compose retuning, or source edits.
- Status: visible Windows defaults are covered; several visible controls and paths remain ungrounded or only partially implemented on Mac.

## Evidence Baseline

### FACT

- Windows UI-surface capture is `refs/win_references/olm_reference_return_windows_20260703_combined/OLMmulti-effectUIsurfacecapture/reference_manifest.json`, case `ui_surface_olmkirakira`.
- Windows fresh defaults/ranges are `refs/win_references/olm_fresh_instance_defaults_20260629/OLMmulti-effectdefaultcapture/reference_manifest.json` and `refs/win_references/olm_fresh_instance_ranges_20260629/OLMmulti-effectrangecapture/reference_manifest.json`.
- The committed parity result says `OLMKiraKira` defaults are `fixed`; ranges are `mostly-fixed` with `source-no-range: 11` and `windows-no-range: 1`: `refs/conformance/windows_fresh_param_parity_20260703.md`.
- The current source-backed Mac schema is `refs/reports/mac_plugin_param_schema_20260629.json` / `.md`, generated from `mac/OLMKiraKira/OLMKiraKira.cpp`.
- The Windows UI surface starts with `Channel`, `Blur Mode`, `Merge mode`, `Approximated Input`, then brightness/strength/fade/opacity and the ray/ramp groups. The Mac `ParamsSetup` source order starts with `Glow Rotation`, `Brightness Gain`, lengths, radius, opacity, then `Channel` and `Blur Mode` (`mac/OLMKiraKira/OLMKiraKira.cpp`, `ParamsSetup`).
- The current IR explicitly covers the 8bpc Software ray path and Merge mode 1, including the Blur Mode 2 three-box-filter path: `notes/IR_OLMKiraKira.md`.

### INFERENCE

- A `source-no-range` color/custom row is not by itself a missing control: Windows also reports no scalar range for colors and custom ramp rows. The actionable gaps below are controls whose value/path is not consumed, whose custom UI is absent, or whose ordering/units are not proven equivalent.
- The historical hotspot witness cannot be used to close these gaps. The Windows traced sample and historical Mac compose witness agree at 144 while the canonical PNG is 131: `refs/conformance/olmkirakira_reference_provenance_audit_20260701.md` and `refs/conformance/olmkirakira_hotspot_lane_audit_20260701.md`.

## Covered / Do Not Reopen

- `Channel` choices/range (`1..4`) and default are covered at the UI-schema level. The current IR has a grounded Channel-2 seed fact, but other channel semantics still need dedicated behavior witnesses if they become an active lane.
- `Strength multiplier`, `Glow Opacity`, `Fade Out` range declaration, `Highlight Radius` range declaration, labels (`Merge mode`, `Strength multiplier`, `Diagonal 2 length`, `Diagonal Color2`), and fresh defaults are covered by the 2026-07-03 host/UI cleanup and parity snapshot. Coverage of a declaration does not imply render-path coverage for the controls called out above.
- Vertical/horizontal/diagonal/diagonal2 lengths and their ordinary color inputs are represented in the current source and current IR ray aggregation path. Their exact Windows equivalence remains bounded by the existing guarded 8bpc/Software IR.
- Do not retune BT.709 seed, boxFilter, ray-helper choreography, `FUN_18114fd90` aggregation, Merge mode 1 compose, gain scale, or final quantization from this audit. The hotspot lane remains frozen under `refs/conformance/olmkirakira_hotspot_lane_audit_20260701.md`.
