# リポジトリと解析証拠の管理方針

このプロジェクトでは、移植ソースと再現可能な小型fixtureを公開候補とし、元のWindows
プラグイン、AEの実行出力、クラッシュダンプ、作業機固有の記録はローカル解析資料として
扱います。解析資料が必要であることと、GitHubで公開してよいことは同義ではありません。

## 追跡するもの

- `mac/`, `shared/`, `cli/` の移植実装
- `scripts/`, `tools/` の再現・検証コード
- 小型で出所を説明できるfixture
- ハッシュ、差分集計、実行条件など、第三者バイナリを含まない証拠
- 完成範囲と未証明境界を説明する文書

## ローカルに保持するもの

- 元の `.aex`、公式配布ZIPおよびその展開物
- Windows/Mac AEの生レンダーと連番EXR
- `mac_validation_runs/` の実行ディレクトリ
- AE自動保存、クラッシュダンプ、ログ、テンポラリ
- 個人の絶対パスを含む未正規化のreturn

これらは解析に必要なら作業ツリー外のローカル資料庫へ保管します。公開用リポジトリへは、
必要な事実だけを正規化したJSON/Markdownとして戻します。

## 公開前ゲート

公開候補は次を満たす必要があります。

1. `python3 scripts/audit_public_repository.py` が成功する。
2. 元のWindows `.aex`を含むZIPがない。
3. APIキー、秘密鍵、Cookie、個人の絶対パスがない。
4. ライセンスと第三者由来資料の扱いがREADMEから確認できる。
5. 公開用の履歴は、非公開解析資料を一度も含まないクリーンな履歴から作る。

現在の開発リポジトリには過去の非公開解析資料が履歴に含まれるため、可視性を直接
Publicへ変更しません。公開時は許可されたパスだけを新しい履歴へコピーします。

## 解析を追加するとき

生データはローカルrunへ出力し、コミットする証拠は次の最小構成にします。

- 入力fixtureの由来とSHA-256
- 対象プラグイン、AE版、色深度、geometry、パラメータ
- 比較対象のSHA-256
- exact/differentの判定と、異なる場合の統計
- その証拠が閉じる経路と、閉じない経路

同一分岐の近接値を増やすより、未確認の色深度、境界値、geometry、ホスト経路を優先します。
