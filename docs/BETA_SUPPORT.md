# 検証の方法と結果

[English](BETA_SUPPORT.en.md)

## 比べ方

元のWindows版プラグイン（`.aex`）そのものと比べています。元のプラグインは、命令を1つずつ再現して動かすエミュレーターの上で動かしています。

同じ素材と設定を両方に渡し、出てきた画像をバイト単位で比べます。描いた範囲も含めて、1ビットでも違えば不合格です。

## 試している条件

素材・設定・サイズなどは、乱数で組み合わせています。

- 素材：ふつうの画像のほか、半透明の画素や、32 bpcの明るすぎる値・特殊な値（NaNなど）を含むもの
- 設定：各パラメーターを、UIで選べる範囲からランダムに選びます
- 色深度：8／16／32 bpc
- サイズ：1×1〜1920×1080。幅と高さは奇数と偶数を半々で選び、1ピクセル幅の細長い画像も含みます
- AEからの描画の頼まれ方：
  - プレビュー解像度（フル〜1/8、縦と横で違う倍率も）
  - 拡大表示などで、画像の一部だけを描くとき
  - プラグインが周りに余白を必要とするとき
  - メモリの行の末尾に余白があるとき

食い違いが見つかったら、再現する最小の例まで自動で絞り込んで保存し、修正のたびに全部やり直して確かめています。

## 結果

AEがふだん使う描画方法（Smart Render）で比べています。OLMSmootherだけは、Windows版が対応している従来の方法で比べています。

- 奇数・偶数のサイズを中心にした3000件と、部分描画を中心にした1000件で、Windows版が描画できた条件はすべて一致しました。途中で見つかった食い違いは、すべて直してあります。
- Windows版自体がエラーになる条件や、エミュレーターで時間内に終わらない条件は比べられないので、数に入れていません。

## 実際のAfter Effectsでの確認

- macOS版After Effects 2026で、10本とも読み込み・適用・レンダーができることを確認しています。
- 1920×1080と3840×2160の実寸でも本物のプラグインを動かし、描画できないケースや処理時間を調べて、見つかった問題を直しました。

## 比べていないこと

- Windows版After Effectsで実際に書き出した画像とは比べていません。比べているのは、元のプラグインをエミュレーターで動かした結果です。
- エミュレーターで扱えるのは1920×1080までです。それより大きいサイズは、同じ処理がそのまま当てはまる前提です。
- GPUレンダー、AEの色管理、素材の読み込み・書き出しの違いは対象外です。

ほかの制限は[既知の制限](../KNOWN_LIMITATIONS.md)を見てください。
