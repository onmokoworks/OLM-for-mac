# OLMColorKey Edge Thin Caller/Stage Probe 20260717

This evidence is deliberately split. The callers are verified statically from
the checked-in assembly, while the AEX stages are invoked directly under local
Unicorn. Neither `FUN_180009000` nor `FUN_1800094B0` is executed. This is not
AE-host execution and makes no PNG or AE-exact claim.

## Corrected caller boundary

- `FUN_180009000` is the only immediate caller of `FUN_180008320`. Its type-2
  path is `FUN_180008AD0 -> FUN_1800058A0 -> FUN_180008320`.
- `FUN_1800094B0` is a separate 8-bit path. It executes
  `FUN_180008C90 -> FUN_180005D60` and then performs inline
  threshold/write loops; it does not call `FUN_180008320`.
- Both callers move the same value from `0x18001F754` into `XMM3`. In the
  hash-pinned AEX, the raw bytes are `00 00 7a 45`, or `4000.0f`, not `0.5f`.
  This contradicts the audit's numeric assertion while confirming its
  `MOVSS XMM8` / `MOVAPS XMM3` data flow. `FUN_180009000` separately forwards
  `R14+0x40` directly to the erode leaf in `XMM1`, with no intervening amount
  arithmetic.

## Executed evidence

The 8-bit probe executes only its seed and type-2 distance stages with the
pinned caller value `XMM3=4000.0`. It is retained as independent evidence for the static
`FUN_1800094B0` ABI and is not presented as input to `FUN_180008320`.

The connected 16-bit probe matches the actual `FUN_180009000` stage family:

1. `FUN_180008AD0` writes an 8-byte-per-pixel boundary world.
2. That exact world is passed to `FUN_1800058A0` with `XMM3=4000.0`, producing a
   16-byte-per-pixel float distance world.
3. That exact distance-world pointer is passed as stack argument 6 to a direct
   `FUN_180008320` call. The work world is supplied in both `RDX` and stack
   argument 5, matching `0x1800093F5..0x18000941D`; destination pixels are
   8 bytes.

All three connected calls return `RAX=0`. A second connected diagnostic repeats
the same direct chain with the audit-requested `XMM3=0.5`; it is explicitly not
classified as the pinned caller value. The JSON records the distance-world
SHA-256 immediately before and after the leaf, proving pointer-content
continuity, plus the complete destination bytes. An independent portable
oracle matches the complete output, including untouched sentinel bytes.

## Oracle limit

The portable oracle starts from the float32 buffer generated by the AEX leaf.
It independently checks source/matched selection, float32 multiplication,
truncate-toward-zero conversion, low-word storage, and preserved destination
bytes. It does not independently derive the leaf's float-generation buffer.
