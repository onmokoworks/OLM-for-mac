## INFERENCE

- For float input, OpenCV 4.5.5 auto sizing gives `round(sigmaX * 8 + 1) | 1`; with integer length and `sigmaX=length*0.5`, this is exactly `4*length+1`.
- OpenCV 4.5.5's arm64 row dispatch explains the old mismatch signature: a five-tap symmetric nested-FMA path for length 1; first-tap multiplication followed by ordered FMA for generic four-lane vector output; and non-fused multiplication/addition for the scalar tail.
- This accumulation-path identification is controlled-sidecar/source evidence, not an actual-AEX observation. The AEX evidence grounds the call contract.
- The locally emulated AEX output is reproduced by a 21-tap uniform float kernel (`1.0f/21.0f` per tap) with left-to-right non-fused float accumulation. The uniform-kernel classification remains diagnostic until the coefficient buffer is captured in a live Windows process.
- The arm64 cv2 4.5.5 Gaussian profile and its 85/85 result are secondary and are retained independently through `prepare()`.
